# Hierarchical EML Output Head — Stable Variant (K = M = d = 225)

A two-level coordinate-matching language-model head that replaces the dense
[d x V] projection with an O(sqrt(V)) cluster->word scheme.

The score is the numerically stable surrogate of the EML operator
eml(u, v) = exp(u) - ln(v):

    S = alpha * U  -  beta * log( softplus(V) + eps )
                                  \_____________/
                                        R

  U     -- main semantic similarity channel
  V     -- correction / gating channel (fed through softplus so log always
           sees a positive argument)
  alpha, beta  -- learned per-level temperatures
  coordinates are FIXED; only the projections and temperatures are trained
  separate projections per channel (preferred over splitting one query in half)

  softplus(x) = log(1 + exp(x))

    A smooth, always-positive function used to make log(V) safe to compute.
    V is a cosine similarity in [-1, 1], so it can be negative — log of a
    negative number is undefined. softplus(V) is always > 0 regardless of
    the sign of V, so log(softplus(V) + eps) never fails.

    Behavior:
      x = -3  ->  0.049   (near zero but never zero)
      x =  0  ->  0.693
      x =  3  ->  3.049
      x = 10  ->  10.000  (approaches x for large positive values)

    It is a smooth version of ReLU = max(0, x).
    ReLU has a sharp corner at x=0; softplus curves through it smoothly,
    which keeps gradients flowing even when V is negative.

-------------------------------------------------------------------------------
DIMENSIONS
-------------------------------------------------------------------------------

  L   sequence length          450
  d   hidden size              225
  V   vocabulary size       50,280
  K   number of clusters       225
  M   words per cluster        225
  K*M addressable slots     50,625
      padding slots (K*M-V)    345

  Note: d = K = M = 225. This alignment is intentional — it means the
  cluster coordinate matrices C_u, C_v can be exactly orthogonal (see
  Parameters section below).

Padding: because K*M = 50,625 > V = 50,280, slots 50,280..50,624 do not
correspond to real tokens. Concretely: cluster 224 is entirely padding, and
cluster 223 is padding for local indices 105..224. A boolean mask
valid[K][M] marks real slots. Padding slots get logit -inf in the word
softmax and are never used as targets.

-------------------------------------------------------------------------------
PARAMETERS
-------------------------------------------------------------------------------

Trainable projections (four 225x225 matrices):

  W_uc, W_vc, W_uw, W_vw   shape [225 x 225]

Learned scalars (four single f32 values):

  alpha_c, beta_c   -- temperature weights for the cluster scoring step
  alpha_w, beta_w   -- temperature weights for the word scoring step

  Each is one number, not a vector or matrix. It is multiplied against
  every element of the entire [L x K] (or [L x M]) score matrix uniformly:

    alpha_c = 2.0  means "scale up the U channel contribution by 2x
                   for every token and every cluster simultaneously"

  They control the balance between the U and V channels at each level.
  If beta converges toward 0 during training, the V channel is not
  contributing and the head reduces to pure cosine routing via U alone.

  These four scalars account for the "+ 4" in the trainable parameter
  count:  4 * 225^2 + 4 = 202,504

Fixed coordinates (created once before training, never updated):

  C_u, C_v          shape [K x 225]         (cluster coords, one row per cluster)
  W_u, W_v          shape [K x M x 225]     (word coords, one row per word slot)

  Where they come from:

    Option A — from pretrained embeddings (recommended):
      1. Take the embedding matrix of a pretrained model: shape [V x 225].
         Each of the 50,280 rows is the 225D vector for one vocabulary token.
      2. Run k-means with K=225 clusters on those vectors.
         This groups semantically similar tokens together.
      3. The 225 cluster centroids become the rows of C_u and C_v
         (you can use the same centroids for both channels, or derive
          C_v from a second run / a different embedding layer).
      4. Assign each token to its nearest centroid.
         Within each cluster, sort the M=225 token slots and store their
         embedding vectors as rows in W_u[k] and W_v[k].

    Option B — random Gaussian (quick start, lower quality):
      C_u = random_normal(shape=[225, 225])
      W_u = random_normal(shape=[225, 225, 225])
      Then L2-normalize every row (step 3 of the forward pass).

      The problem: the 225 cluster positions are now random points in 225D
      space with no connection to language. For example, cluster 17 might
      accidentally group "dog", "justice", and "seventeen" together simply
      because their random coordinates happen to be close.

      The projection matrices W_uc/W_vc (the "router") must then spend
      training time discovering which cluster actually means what — they
      have to build the semantic map from zero, using only the gradient
      signal from cross-entropy loss.

      With Option A the clusters already correspond to semantic groups
      (e.g. cluster 17 = past-tense verbs) before training starts. The
      router just needs to learn a small alignment between the transformer
      hidden states and that pre-existing structure — much faster and more
      reliable.

    Option C — exact orthogonal init (possible because d = K = 225):

      Because the hidden dimension d equals the number of clusters K,
      both equal 225, the cluster coordinate matrix C_u has shape [225 x 225]
      — a square matrix. A square matrix can have all rows exactly mutually
      orthogonal. All pairwise dot products are exactly 0 — maximum separation.

      How to construct an orthogonal matrix (Rust — no external crate needed):

        Method 1 — Identity (simplest):

          Q[i][j] = 1.0  if i == j
                  = 0.0  otherwise

          Row i is the standard basis vector with a single 1 at position i.
          All rows are perfectly orthogonal by construction.

          Side effect: Uc = Qu_c @ C_u.T = Qu_c @ I = Qu_c
          The coord lookup disappears — cluster scoring becomes a plain
          linear classifier. Still valid, just loses the EML character
          at the cluster level.

        Method 2 — Random orthogonal via Modified Gram-Schmidt (recommended):

          This is the algorithm behind QR decomposition, implemented directly.
          No linear algebra crate required — just a random number generator.

          Input:  n x n matrix G filled with random Gaussian values
          Output: n x n orthogonal matrix Q (same shape, all rows unit length
                  and mutually orthogonal)

          Step 1 — Fill G with random Gaussian values:
            For each element g[i][j]:
              Draw two uniform random numbers u1, u2 in (0, 1).
              Apply Box-Muller transform:
                g[i][j] = sqrt(-2 * ln(u1)) * cos(2 * PI * u2)
              This produces a value from a standard normal distribution.

          Step 2 — Modified Gram-Schmidt orthogonalization:
            For i = 0 to n-1:

              (a) Copy row i of G into a working vector v:
                    v[k] = G[i][k]   for k = 0..n-1

              (b) Subtract the projection of v onto every previous row q_j:
                    For j = 0 to i-1:
                      proj = dot(v, Q[j])        // scalar: sum of v[k]*Q[j][k]
                      v[k] -= proj * Q[j][k]     // for each k

                  After this loop, v is orthogonal to all previous rows.

              (c) Normalize v to unit length:
                    norm = sqrt( sum of v[k]^2 )
                    v[k] /= norm                 // for each k

              (d) Store v as row i of Q:
                    Q[i][k] = v[k]              // for each k

          Why "Modified" Gram-Schmidt:
            The classical version subtracts all projections using the
            ORIGINAL v. The modified version subtracts each projection
            one at a time, updating v after each subtraction. This makes
            the result numerically stable — rounding errors do not
            accumulate across the 225 rows.

          Result: Q is a 225x225 matrix where:
            dot(Q[i], Q[j]) = 0.0  for all i != j  (orthogonal)
            dot(Q[i], Q[i]) = 1.0  for all i       (unit length)

          Generate C_u and C_v independently by running this algorithm
          twice with different random seeds.

      After construction, store as a fixed constant — never update during
      training and never include in the optimizer parameter list.

      In 225D, random unit vectors have expected pairwise dot product = 0
      and std = 1/sqrt(225) = 0.067 — already very close to orthogonal.
      Gram-Schmidt makes this exactly 0 for all pairs.

      Why Option A (pretrained centroids) is still preferred:
        Orthogonal init gives perfectly separated clusters but the cluster
        assignments are still arbitrary — cluster 17 still has no semantic
        meaning. Option A gives both separation AND meaning, so the router
        starts with a useful map rather than an empty one.

    Option D — Laplacian spectral coordinates (vocabulary graph geometry):

      Idea from spectral graph theory: the eigenvectors of the graph Laplacian
      encode the "geometric DNA" of a graph. Applied to the vocabulary:

        1. Build a vocabulary similarity graph where:
             nodes  = all 50,280 tokens
             edges  = weighted by co-occurrence frequency or cosine similarity
                      of pretrained embeddings
           Adjacency matrix A[i][j] = similarity between token i and token j.

        2. Compute the normalized Laplacian:
             D = diagonal matrix where D[i][i] = sum of row i of A
             L = I  -  D^(-1/2) @ A @ D^(-1/2)

        3. Compute the 225 smallest eigenvectors of L:
             L @ v = lambda * v
             Keep eigenvectors v_1, v_2, ..., v_225 (sorted by eigenvalue).

        4. Each token i gets a 225D coordinate from the i-th row across
           all 225 eigenvectors:
             token_coord[i] = [ v_1[i], v_2[i], ..., v_225[i] ]

        5. Group tokens into K=225 clusters (e.g. by k-means on these coords).
           The cluster centroid in spectral space becomes a row of C_u.
           Token coords within a cluster become rows of W_u[k].

      Why this is better than k-means on raw embeddings (Option A):
        Low-frequency eigenvectors capture large-scale semantic groups
        (nouns, verbs, function words). High-frequency eigenvectors capture
        fine-grained distinctions within those groups. The coordinate geometry
        directly reflects relational structure — tokens that co-occur or are
        semantically similar are close in spectral space by construction,
        not just by accident of the embedding training.

      The U/V channel split maps naturally onto this:
        C_u = spectral coords from a semantic similarity graph
              (structural similarity — like NeRF density, position-dependent)
        C_v = spectral coords from a syntactic co-occurrence graph
              (correction channel — like NeRF color, direction-dependent)

      Footnote — NeRF-style sinusoidal encoding:
        NeRF positional encoding earns its keep because spatial coordinates
        have a real metric: nearby (x,y,z) points share density and color.
        The encoding imposes a smoothness prior that matches the signal.

        Cluster indices do NOT have this property. BPE/NeoX token IDs are
        assigned by merge/frequency order, not meaning. Cluster 17 and
        cluster 18 (buckets [3825,4050) and [4050,4275) of the token ID
        space) have no reason to be semantically adjacent. Encoding k with
        Fourier features of its arbitrary integer label imposes smoothness
        over a structure that is not there. Failure modes:

          False adjacency: low-frequency bands dominate the norm, so
          pos_enc(k) and pos_enc(k+1) have cosine similarity near 1.
          Adjacent buckets look nearly identical to the router — the
          opposite of Option C which drives all pairwise cosines to 0.

          1D-manifold confinement: pos_enc(·) is a deterministic function
          of the scalar k, so all 225 cluster coordinates lie on a single
          1D curve in 225D space. Random Gaussian fills the space; orthogonal
          init maximally separates; Fourier encoding strings every cluster
          along one curve — a capacity liability for 225 unordered categories.

          Frequency mismatch: beyond band ~9 (where 2^i > K), one period
          spans less than a single index step. Those bands behave like
          deterministic pseudo-random hashing, not structured encoding.

        Sinusoidal encoding IS appropriate under one condition: if the
        clusters are first sorted along the Fiedler vector (the second
        eigenvector of L, which gives the best 1D spectral ordering), then
        adjacent indices ARE semantically adjacent and a smooth multi-scale
        encoding adds genuine structure. But at that point Option D's spectral
        coordinates already provide the full geometry directly, in 225D rather
        than on a curve, so Fourier features of a Fiedler-ordered index are a
        strictly worse-conditioned reparameterisation of Option D.

  All options freeze these matrices after initialization.
  The trainable projections W_uc / W_vw learn to map hidden states
  into the same space as the fixed coords.

  Recommended implementation order:

    Step 1 — Option C (Gram-Schmidt orthogonal) everywhere.
      Cheap to implement (no external data needed), theory-backed, and it
      is the control experiment that answers the foundational question:
      does fixed coordinate geometry matter at all, or does the router
      learn everything regardless of init? Until this is answered, spending
      effort on spectral coordinates is premature.

    Step 2 — If C is shown insufficient, test a split variant:
      Cluster coords:  keep Option C (orthogonal)
      Word coords:     replace with Option D spectral slabs

      The mechanism is asymmetric: cluster routing needs maximal separation
      (Option C delivers this exactly), while word coords within a cluster
      benefit from semantic structure because those 225 words are a
      coherent group and their intra-cluster geometry is real. This is the
      cheapest way to introduce spectral structure — you only need the
      per-cluster local eigenvectors, not a full 50k-node Laplacian solve.

    Step 3 — Full Option D (spectral everywhere) only after Step 2 shows
      the word-slab structure is load-bearing.
      Lanczos for 225 eigenvectors of a 50,280-node sparse Laplacian is
      real engineering work (memory, convergence, numerical stability).
      Do not pre-pay that cost until Steps 1 and 2 justify it.

Trainable parameter count:  4 * 225^2 + 4 = 202,504

-------------------------------------------------------------------------------
FORWARD PASS
-------------------------------------------------------------------------------

Step 1 — Transformer output
  H                 shape [L x 225]

Step 2 — Cluster projections
  Qu_c = H @ W_uc   shape [L x 225]
  Qv_c = H @ W_vc   shape [L x 225]

Step 3 — L2 normalize (row-wise)

  Every row is a 225-dimensional vector. For each row independently:
    1. Compute the L2 norm of that row:
         norm = sqrt( x[0]^2 + x[1]^2 + ... + x[224]^2 )
    2. Divide every element of that row by norm:
         x[i]  <-  x[i] / norm     for i = 0..224

  Applied to each matrix:

    Qu_c  shape [L x 225]:    normalize each of the L token rows
    Qv_c  shape [L x 225]:    normalize each of the L token rows
    C_u   shape [K x 225]:    normalize each of the K cluster rows
    C_v   shape [K x 225]:    normalize each of the K cluster rows

  Concrete example for one row of C_u (225 numbers -> unit vector):
    before:  [0.3, -1.2, 0.8, ..., 0.1]
    norm  =  sqrt(0.3^2 + 1.2^2 + 0.8^2 + ... + 0.1^2)  =  e.g. 2.47
    after:   [0.3/2.47, -1.2/2.47, 0.8/2.47, ..., 0.1/2.47]
          =  [0.121, -0.486, 0.324, ..., 0.040]

  After normalization every row has length 1.0, so the dot products in
  step 4 (Uc = Qu_c @ C_u.T) become cosine similarities: values in [-1, 1].

Step 4 — Cluster similarities
  Uc = Qu_c @ C_u.T   shape [L x K]
  Vc = Qv_c @ C_v.T   shape [L x K]

Step 5 — Stable nonlinear score
  Rc = log( softplus(Vc) + eps )
  Sc = alpha_c * Uc  -  beta_c * Rc

  What this does:

  After step 4, each token has two similarity vectors against all 225 clusters:
    Uc[t, k] = how well token t matches cluster k via the U channel  (in [-1, 1])
    Vc[t, k] = how well token t matches cluster k via the V channel  (in [-1, 1])

  A simple dot-product head would use only one channel: score = Uc.
  This formula combines both channels nonlinearly, inspired by the EML
  operator exp(u) - ln(v):

    Uc  contributes POSITIVELY to the score.
        High Uc -> token strongly matches this cluster -> score goes up.

    Rc  contributes NEGATIVELY (subtracted).
        Rc is a compressed version of Vc:
          Vc = -1.0  ->  Rc = log(softplus(-1) + eps) = log(0.313) = -1.16
          Vc =  0.0  ->  Rc = log(softplus( 0) + eps) = log(0.693) = -0.37
          Vc =  1.0  ->  Rc = log(softplus( 1) + eps) = log(1.313) =  0.27
        High Vc -> high Rc -> score goes DOWN.

  Practical effect: a cluster wins only if BOTH channels agree on it.
    - U says "yes" but V says "no"  ->  Sc is pulled down by beta_c * Rc
    - U says "yes" and V says "yes" ->  both terms reinforce the score

  V therefore acts as a gating / correction channel that can suppress a
  cluster even when U similarity is high. This gives the head more
  discriminating power than a single cosine similarity could provide.

  alpha_c and beta_c are single f32 scalars — one number each, not vectors.
  The same alpha_c value is broadcast across the entire [450 x 225] matrix Uc,
  scaling every element identically. They control how strongly each channel
  influences the final score. If beta_c converges to ~0 during training, the
  V channel is not helping and the head falls back to pure cosine routing via U.

Step 6 — Cluster probabilities
  Pc[t, k] = softmax( Sc[t, :] )   shape [L x K]

Step 7 — Teacher-forced cluster gather
  For target token v*:
    c* = floor( v* / 225 )      -- which cluster
    w* = v* mod 225             -- which word inside that cluster

  Gather the coord slabs for cluster c* only (skip the other 224):
    W_u[c*]   shape [M x 225]
    W_v[c*]   shape [M x 225]

Step 8 — Word projections
  Qu_w = H @ W_uw   shape [L x 225]   (normalize as in step 3)
  Qv_w = H @ W_vw   shape [L x 225]

Step 9 — Word similarities (each token vs its gathered slab)
  Uw[t, m] = dot( Qu_w[t], W_u[c*_t, m] )
  Vw[t, m] = dot( Qv_w[t], W_v[c*_t, m] )
  both shape [L x M],  M = 225

Step 10 — Word scores
  Rw = log( softplus(Vw) + eps )
  Sw = alpha_w * Uw  -  beta_w * Rw

Step 11 — Word probabilities with padding mask
  For each token t, set Sw[t, m] = -inf  where (c*_t, m) is a padding slot.
  Pw[t, :] = softmax( Sw[t, :] )

Step 12 — Loss
  L_c = -sum_t  log Pc[t, c*_t]
  L_w = -sum_t  log Pw[t, w*_t]
  L   = L_c + L_w

-------------------------------------------------------------------------------
BACKWARD PASS
-------------------------------------------------------------------------------

Step 1 — Softmax + cross-entropy
  dSc = Pc - Yc
  dSw = Pw - Yw
  (Yc, Yw are one-hot targets; masked padding columns of dSw are zero.)

Step 2 — Through S = alpha*U - beta*R
  dU = alpha * dS
  dR = -beta  * dS

  If alpha/beta are learned:
    d_alpha = sum( U * dS )
    d_beta  = sum( -R * dS )

Step 3 — Through R = log( softplus(V) + eps )
  Let sig(V) = sigmoid(V) = 1 / (1 + exp(-V))

  dR/dV = sig(V) / ( softplus(V) + eps )
  dV    = dR * sig(V) / ( softplus(V) + eps )

  This gradient is BOUNDED for all V — the key improvement over the raw
  -1/V gradient of ln(v).
    V -> +inf:  sig(V) -> 1, softplus(V) -> V, ratio -> 1/V -> 0
    V -> -inf:  sig(V) -> 0, softplus(V) -> 0, denominator -> eps (not 0),
                so ratio -> 0/eps = 0, not 1.
                (The "ratio -> 1" claim holds only in the eps=0 idealisation.
                 With eps > 0 the derivative peaks near 1 for moderately
                 negative V (roughly -3 to -8, where e^V >> eps so numerator
                 and denominator are asymptotically equal), then falls back
                 toward 0 as V approaches log(eps) and beyond.)

  Operationally this is moot: V is a cosine similarity confined to [-1, 1].
  Actual values across the reachable range (eps ignored, negligible effect):
    f(-1) = sigmoid(-1) / softplus(-1) = 0.2689 / 0.3133 ≈ 0.858
    f( 0) = sigmoid( 0) / softplus( 0) = 0.5000 / 0.6931 ≈ 0.721
    f(+1) = sigmoid(+1) / softplus(+1) = 0.7311 / 1.3133 ≈ 0.557
  The derivative is monotonically decreasing across [-1, 1], so the
  reachable range is roughly [0.56, 0.86] — bounded, well-conditioned,
  no blow-up at any reachable value.

Step 4 — Through the dot products
  Cluster path:
    dQu_c = dUc @ C_u
    dQv_c = dVc @ C_v

  Word path (per token, against the gathered slab):
    dQu_w[t] = dUw[t] @ W_u[c*_t]
    dQv_w[t] = dVw[t] @ W_v[c*_t]

  Note: if coords are ever unfrozen, symmetric expressions give dC / dW.

  The L2 normalization in step 3 inserts a Jacobian between these gradients
  and the projections:  d(q_hat)/dq = ( I - q_hat q_hat^T ) / ||q||
  Standard L2-norm backward; stays bounded.

Step 5 — Through the linear projections
  dW_uc = H.T @ dQu_c
  dH   += dQu_c @ W_uc.T
  (repeat for the other three projection matrices)

Step 6 — Total hidden gradient
  dH = dH_(u,c) + dH_(v,c) + dH_(u,w) + dH_(v,w)

-------------------------------------------------------------------------------
INFERENCE
-------------------------------------------------------------------------------

1. Compute cluster scores Sc.
2. Take top-k clusters (k=2 or 4), NOT top-1.
   Top-1 routing errors are unrecoverable — wrong cluster means wrong word.
3. Evaluate word scores only inside the selected slabs (with the padding mask).
4. Global argmax over the JOINT score, not the word score alone:

     score(c, w) = log Pc[c]  +  log Pw[w | c]

   This is load-bearing under top-k routing. Pw[w|c] is a conditional
   distribution normalised only over the M=225 words inside cluster c.
   A cluster with a peaky internal distribution can produce high Pw values
   even if the router assigned it low probability. Without the log Pc[c]
   term you will preferentially pick words from the peakiest slab rather
   than the cluster the router actually favours.

   Under top-1 routing this term is constant across all candidates and
   can be dropped, but top-1 is discouraged (see step 2).

Complexity: O(k * sqrt(V))

-------------------------------------------------------------------------------
COMPUTATIONAL COST
-------------------------------------------------------------------------------

Dense LM head per token:
  V * d  =  50,280 * 225  =  ~11.3M multiply-adds

This head per token (teacher-forced training):
  2*K*d + 2*M*d  =  2*225*225 + 2*225*225  =  202,500 multiply-adds

~56x fewer than the dense head.

-------------------------------------------------------------------------------
WHAT THIS ARCHITECTURE REALLY IS
-------------------------------------------------------------------------------

Conceptually closer to semantic retrieval / vector routing / hierarchical ANN
search / MoE gating / product quantization than to a classical LM head.

The load-bearing component is most likely fixed semantic geometry + a tiny
learned router, not the nonlinear EML-style score itself.

Design note — the d = K = M = 225 triple coincidence:

  This spec fuses three distinct quantities into the same value 225:
    d_model      the transformer hidden size
    d_coord      the coordinate space dimension (size of each coord vector)
    K            number of clusters
    M            words per cluster

  The orthogonality argument only requires K <= d_coord. It does NOT
  require d_coord = d_model. The projection matrices W_uc etc. have shape
  [d_model x d_coord] and do not need to be square — a backbone with
  d_model = 768 maps 768 -> 225 just fine, keeping K = 225 clusters with
  exact orthogonal coords while the backbone runs at its natural width.

  The triple coincidence is elegant but couples this output head to a
  225-wide backbone for no structural reason. It also sits in mild tension
  with Option A init: centroids of pretrained embeddings will NOT be
  orthogonal, so the orthogonal-init path and the semantic-init path are
  largely mutually exclusive in practice. Choose one deliberately rather
  than assuming both apply simultaneously.

Recommended experimental controls:

  Baseline A:  drop the V/R channel entirely (beta=0) -> pure cosine routing.

  Baseline B:  replace the stable score with a plain bilinear logit U and a
               standard hierarchical softmax.
               If A/B match this head's perplexity, the EML surrogate is
               decorative and the geometry is doing the work.

  Coordinate init:  use centroids of pretrained embeddings + per-cluster local
                    PCA rather than random Gaussian. The fixed coords carry the
                    inductive bias that the dense head's trained params would
                    otherwise carry.
